# Отправка объявления — контракт формы

Форма `composer.html` отправляет одно объявление одним запросом. Адрес задаётся в `<meta name="om-announce-endpoint" content="...">`. Если адрес пустой, форма ничего не отправляет: она показывает JSON, который ушёл бы на сервер.

## Запрос

```
POST <om-announce-endpoint>
Content-Type: application/json
Idempotency-Key: <uuid>
```

```json
{
  "type": "system.announcement",
  "payload": {
    "audience": { "org_type": 100, "level": 4, "region_id": 6, "district_id": 606, "mahalla_id": 606008 },
    "severity": "warning",
    "expires_at": "2026-08-15T13:00:00Z",
    "texts": {
      "uz": { "title": "Profilaktika ishlari", "body": "..." },
      "ru": { "title": "Профилактические работы", "body": "..." }
    }
  }
}
```

`type` и `payload` соответствуют колонкам вставки `select e.id, 'system.announcement', jsonb_build_object(...)`. `event_id` форма не отправляет: его выдаёт сервер, и он же кладёт его в `payload`.

| Поле | Значения |
|---|---|
| `audience.org_type` | целое число от 1 до 999999, по умолчанию 100 |
| `audience.level` | 1 — вся республика, 2 — область, 3 — район или город, 4 — махалля |
| `region_id` / `district_id` / `mahalla_id` | передаются только до выбранного уровня; ключи ниже уровня отсутствуют, `null` не передаётся |
| `severity` | `info`, `warning`, `critical` |
| `expires_at` | ISO-8601 в UTC, без миллисекунд. Оператор вводит ташкентское время (UTC+5): 15.08.2026 18:00 → `2026-08-15T13:00:00Z` |
| `texts.*.title` | 1–120 символов (считаются кодовые точки). Пробелы и символы нулевой ширины обрезаются по краям, управляющие символы направления текста (U+202A–202E, U+2066–2069) удаляются |
| `texts.*.body` | 1–600 символов, переносы строк сохраняются |

## Ответ

| Ответ | Что показывает форма |
|---|---|
| `200` / `201` / `202` с `Content-Type: application/json` | «Юборилди»; `event_id` (или `id`) из тела показывается оператору |
| `409` | «Аввал юборилган»: сообщение уже принято, повтора нет |
| `400` / `413` / `422` | «Юборилмади» без кнопки повтора. Ошибки полей читаются из `{"errors": {"texts.uz.title": "текст ошибки"}}` или `{"errors": [{"field": "...", "message": "..."}]}` и выводятся с названием поля |
| `401` / `403` | вход истёк / нет прав, без повтора |
| `408` / `425` / `429` / `5xx`, таймаут, обрыв сети | «Юборилмади» и кнопка «Қайта уриниш» |
| любой другой `2xx` или ответ не в JSON | «Натижа номаълум» и кнопка повтора (тот же ключ) |
| редирект (`3xx`) | считается ошибкой: запрос идёт с `redirect: "error"`, чтобы страница входа не выглядела как успех |

Отправка начинается только после подтверждения «Ҳа, юбориш». Повтор отправляет то же тело с тем же `Idempotency-Key`. Сервер должен вернуть результат первой успешной вставки и не создавать второе объявление. Таймаут 15 с покрывает и заголовки, и тело ответа. Кнопка повтора доступна не чаще раза в 2,5 с и не более 5 раз за 30 с. Если срок `expires_at` истекает раньше чем через минуту, форма не отправляет запрос.

## Что нужно от бэкенда

1. Эндпоинт `POST`, который принимает тело выше и делает вставку в `_event` и в таблицу объявлений одной транзакцией.
2. Хранить `Idempotency-Key` не меньше 24 часов. Повтор с тем же ключом и тем же телом возвращает первый ответ; тот же ключ с другим телом — `422`.
3. Проверять `audience` на сервере: id существуют, район принадлежит области, махалля — району. Проверять, что оператор вправе отправлять на выбранный уровень: форма показывает всю республику любому оператору.
4. Справочник `_region` / `_district` / `_mahalla` с `id`, `name` и численностью населения. В `assets/composer-data.js` сейчас лежит образец: 14 областей, 35 районов и 76 махаллей, id собраны по схеме `district = region*100 + n`, `mahalla = district*1000 + n`. Совпадают с SQL-примером: 6 — Хорезм, 606 — Кушкупир, 606008 — «8-маҳалла “Дўстлик”». Остальные id взяты по той же схеме, их нужно сверить с реестром. Для большого реестра нужен поиск на сервере с `limit`: `GET /regions/search?q=&limit=40`.
